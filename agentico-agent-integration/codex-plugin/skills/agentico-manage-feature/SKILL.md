# Agentico Manage Feature

Use this skill when the user is supervising, resuming, reviewing, answering, publishing, or parking an Agentico feature.

## Contract

The harness owns reasoning, user interaction, and the natural-language conversation. Agentico owns runtime discovery, server startup, REST details, retries, event watching, and state classification through CLI JSON.

Do not inspect runtime files or call REST endpoints directly. Treat Agentico's JSON envelopes and normalized watch events as authoritative.

## Feature-Scoped Context

Keep feature-scoped context: feature id, user goal, selected repos, active phase, current status, open attention request ids, pending review gate, and last terminal or parked snapshot. Refresh that context only with CLI JSON:

```bash
agentico feature detail <feature-id> --json
```

## Active vs Parked

When the feature is active, watch events are the primary source of truth:

```bash
agentico feature manage <feature-id> --json --watch
```

When the feature is parked, stopped, code-ready, published, done, or terminal, use turn-by-turn snapshots:

```bash
agentico feature detail <feature-id> --json
```

Resume only when the user asks to continue or the next action requires an active feature:

```bash
agentico feature action <feature-id> resume --json
```

## Decision Mapping

Map user choices to CLI commands:

- Start, resume, stop, interrupt, retry, rewind, rebase, tweak, refactor, publish, merge, mark done, cleanup, and delete use `agentico feature action <feature-id> <action> --json`.
- Need-user-input, ask-user, and permission prompts use `agentico feature answer <feature-id> --json`.
- Review checkpoints use `agentico feature review <feature-id> --json`.
- Publishing uses `agentico feature action <feature-id> publish --json`.

Examples:

```bash
agentico feature answer <feature-id> --json --input-json '{"kind":"ask-user","request_id":"ask-1","answers":{"decision":"Use the existing API"}}'
agentico feature answer <feature-id> --json --input-json '{"kind":"permission","request_id":"perm-1","decision":"allow"}'
agentico feature review <feature-id> --json --input-json '{"decision":"proceed","phase":"design"}'
agentico feature action <feature-id> publish --json --input-json '{"title":"Implement feature","body":"Generated by Agentico"}'
```

## Response Rules

- Explain what the feature is waiting on in user terms, but do not invent state not present in JSON.
- Ask the user before irreversible actions such as publish, merge, cleanup, or delete.
- Keep watching while active; switch to turn-by-turn snapshots when parked/terminal.
- After every action, refresh with watch or detail before claiming the feature moved state.
