# Testing Baseline

This document is the canonical list of the project's verification tiers and
required Go gates. Run commands from the repository root. Wall times are the
current reference measurements, not budgets, unless a target is stated.

| Tier or gate                          | Command                                                                                   | Current wall time                                                         | Purpose and when to run                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Fast suite                            | `make test-fast`                                                                          | 23s, target <=30s                                                         | Everyday confidence check before every handoff. Runs all Go packages in short mode, with the existing `testing.Short` guards, once and without the race detector.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| E2E smoke shell                       | `bash test/e2e/smoke.sh`                                                                  | 48.53s                                                                    | Builds the binary and checks CLI flags and embedded skill layout. Run when launch behavior, embedded skills, or release packaging may be affected.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Isolated integration                  | `go test ./test/integration/... -count=1`                                                 | 323.06s                                                                   | Covers lifecycle, state-machine, runs-layout, and protocol-violation behavior. Run when those cross-component paths change.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| E2E Go (process-launch / API-driven) | `make test-e2e` | ~8–18m before child race instrumentation; allow 30m | Full process/API suite on Linux amd64 in CI. Race-instruments the test harness and updater child binaries (`AGENTICO_E2E_RACE=1`). Run when process launch, server lifecycle, update transactions, or session boundaries change. |
| Native updater journeys | `make test-selfupdate-native` | 65s on Darwin arm64; allow 15m | Focused real-process installation, endpoint preservation, rollback, cleanup retry, and explicit-stop journeys. CI runs on Darwin amd64/arm64 and Linux arm64 when updater inputs change; Linux amd64 is covered by E2E Go. A manually dispatched CI run always includes all targets. Cross-compilation is not a substitute for these native checks. |
| Updater driver unit/static checks | `make test-selfupdate-driver` | Local/static | Tests and vets the compile-time fixture driver with `agentico_selfupdate_driver`; normal production builds exclude it. CI runs this once on Linux amd64. Run when changing the driver or its production integration. |
| Race regression | `AGENTICO_E2E_RACE=1 go test ./... -count=1 -race -timeout 45m` | Platform-dependent; allow 45m | Extended all-package race/regression sweep, including race-instrumented updater child processes. Run before merging high-risk or concurrency-sensitive changes. This is not the everyday unit command. |
| Live Claude catalog compatibility | `AGENTIC_CLAUDE_CATALOG_LIVE=1 go test ./test/e2e -run '^TestClaudeCatalogLive$' -count=1 -v` | ~1s for three exchanges, plus Go test startup | Opt-in installed Claude Code initialization metadata, without inference. Run when changing Claude model discovery. See [Claude model discovery](claude-model-discovery.md). |
| Live Claude session resume | `AGENTIC_CLAUDE_LIVE=1 go test ./test/e2e -run '^TestClaudeResumeLive$' -count=1 -timeout 10m -v` | ~10–20s for two cheap Haiku turns | Opt-in authenticated inference: a supervisor conversation is rebuilt into a Claude session file and a real Claude resumes it under the pre-assigned id and answers from that history. Runs under a temporary `CLAUDE_CONFIG_DIR`; the credential comes from `CLAUDE_CODE_OAUTH_TOKEN` or a 0600 token file at `$AGENTIC_CLAUDE_LIVE_TOKEN_FILE` (default `~/.config/agentico/claude-live-oauth-token`) and reaches only the Claude child. Skips without either. `AGENTIC_CLAUDE_RESUME_LIVE=1` is accepted as an alias. Run when changing the Claude session converter or supervisor resume. |
| Live Codex session resume | `AGENTIC_CODEX_LIVE=1 go test ./test/e2e -run '^TestCodexResumeLive$' -count=1 -timeout 10m -v` | ~20–60s for two short turns | Opt-in authenticated inference: a supervisor conversation's thread is rebuilt into a Codex rollout and a real Codex resumes it under the adopted thread id and answers from that history. Runs under a temporary `CODEX_HOME` holding a copy of the credentials from the real Codex home (`auth.json`); skips when none exist. The model defaults to a light entry of the installed CLI's own catalog (account availability varies); `AGENTIC_CODEX_RESUME_MODEL` overrides it. Run when changing the Codex rollout converter, the Codex adapter's handshake, or supervisor resume. |
| Live Codex settings change | `AGENTIC_CODEX_LIVE=1 go test ./test/e2e -run '^TestCodexSettingsChangeLive$' -count=1 -timeout 10m -v` | Opt-in, two short turns | Proves the installed Codex CLI accepts `thread/settings/update` for effort and model in a supervisor conversation. Runs under a temporary Codex home and reports the CLI version if the experimental method fails. Passed on codex-cli 0.156.0 (2026-10-07). Run when changing in-place Codex settings. |
| Live Codex compatibility | `AGENTIC_CODEX_LIVE=1 go test ./test/e2e -run '^TestCodexContractLive$' -count=1 -timeout=20m -v` | ~2–3m for two models | Opt-in authenticated inference: structured questions, artifact rejection/repair, fresh threads, and cross-model resume. Run when changing the Codex CLI baseline, model catalog, instruction delivery, or tool protocol. See [Codex phase contract](codex-contract.md). |
| OpenCode HTTP surface probe | `go test ./test/e2e -run '^TestOpenCodeAcpHTTPProbe$' -count=1 -v` | ~1s per binary | No inference. `opencode acp --port <n> --hostname 127.0.0.1` serves OpenCode's HTTP API beside ACP. The health route answers 200 with `OPENCODE_SERVER_PASSWORD` and 401 without it, and `GET /event` opens with `server.connected`. The process exits when stdin closes. Runs on the CLI on PATH, plus the pinned minimum when it is cached; skips when neither is present. Runs under temporary XDG directories. |
| OpenCode pinned-minimum fetch | `make opencode-min-bin` | ~5–20s download | Downloads the OpenCode GitHub release (`anomalyco/opencode`) that matches the provider's `MinVersion()` for the host platform, into `.cache/opencode/<version>/opencode`. Checks that the binary's `--version` matches. Never touches the CLI on PATH. Run this before the pinned-minimum spike; `AGENTIC_OPENCODE_MIN_BIN` can point at another copy instead. |
| Live OpenCode child-permission spike, pinned minimum | `AGENTIC_OPENCODE_LIVE=1 go test ./test/e2e -run '^TestOpenCodeChildPermissionSpikeLiveMinVersion$' -count=1 -timeout 10m -v` | ~10–30s, one delegated turn | Opt-in inference, using raw ACP and HTTP with no adapter code. This is the gate for the supervisor's OpenCode child-session bridge. The prompt makes a sub-agent run a shell command. The child's `bash` `permission.asked` must appear on `GET /event` under a session id that is not the ACP session, and no ACP request may arrive for it. Health must answer 200 with the password and 401 without while the child waits. An HTTP `once` reply must release the child, and the turn must end `end_turn` with the command output. The test asserts that `--version` equals `MinVersion()`. With the variable set, a missing or mismatched binary fails with fetch instructions. The model comes from `AGENTIC_OPENCODE_LIVE_MODEL`, else the configured `small_model`, else `model`; an unavailable model fails with a message naming the variable. Runs under temporary XDG directories holding copies of the user's `auth.json` and config. **Gate result (2026-10-07): passed on OpenCode 1.17.9** (portkey `glm-5-3-flash`). Run when changing the minimum OpenCode version or the bridge. |
| Live OpenCode child-permission spike, installed CLI | `AGENTIC_OPENCODE_LIVE=1 go test ./test/e2e -run '^TestOpenCodeChildPermissionSpikeLiveInstalled$' -count=1 -timeout 10m -v` | ~10–30s | The same round trip and assertions on the `opencode` on PATH; the test logs the installed version. Passed on 1.18.25 (2026-10-07). Run when upgrading OpenCode. |
| Live OpenCode supervisor | `AGENTIC_OPENCODE_LIVE=1 go test ./test/e2e -run '^TestOpenCodeSupervisorLive$' -count=1 -timeout 15m -v` | Allow 15m for three inference turns | Opt-in real coordinator and adapter journey using the installed CLI. Approves a root task spawn and child shell request through the supervisor route, ends the process, seeds prior history into the next generation, recalls a codeword, then approves a root shell request. Passed on OpenCode 1.18.25 (2026-10-07). The model comes from `AGENTIC_OPENCODE_LIVE_MODEL`, else the configured `small_model`, else `model`. OpenCode auth and config are copied into temporary XDG directories; the real OpenCode home is unchanged. Run when changing the interactive profile, child bridge, or history seeding. |
| Desktop static checks                 | `npm run check`                                                                           | 8s                                                                        | Runs TypeScript checks, ESLint, Prettier verification, desktop OpenAPI drift detection, and the canonical error-markup guard. Run for desktop source, tooling, formatting, or API-contract changes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Desktop unit/component/security tests | `npm test && npm run test:security`                                                       | 4s                                                                        | Runs the Vitest renderer, main-process, shared-code, script, and security projects, followed by the explicit security-project gate used by CI. Run for desktop behavior, IPC, preload, policy, or packaging-script changes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Desktop packaged E2E                  | `npm run package:verify && npm run test:e2e:packaged`                                     | ~10m full suite; ~1-2m per targeted spec after the one-time package build | Builds and inspects the native unsigned package, then drives the packaged Electron app and its bundled Go server through the Playwright journey suite. The journeys cover supervision and launch, feature lifecycle and attention flows, planning and review recovery, configuration and workspace restart, history and rewind, publishing and retry behavior, distribution updates, diagnostics, and production security posture. Run for end-to-end desktop workflows, main/server integration, packaging, or distribution behavior — and for **any renderer change that alters user-visible text, roles, or aria-labels**, since the journeys assert on those (see AGENTS.md). Runs locally; scope to the affected specs with `npm run test:e2e:packaged -- test/e2e/journeys/<spec>.spec.ts -g "<test title>"`. On macOS, `npm run e2e:cleanup-handlers` lists (and with `--apply` unregisters) stale `agentico:` URL-handler claims left by old test, build, or dev copies of the app; it is a manual, one-off tool that rewrites LaunchServices claims and can trip endpoint-security monitoring, so it is deliberately not part of any automated step. |
| Desktop release audit                 | `npm run audit:release --workspace desktop && npm run release:verify --workspace desktop` | Local/static                                                              | Checks dependency licenses and provenance, lockfile and module integrity, desktop protocol and hardened-runtime configuration, digest-pinned Linux toolchains, the local `make release` ordering, GoReleaser target/manifest configuration, and updater Ed25519 trust-root semantics. `make release` additionally performs machine/credential/image preflight and post-build provenance rechecks. Run for dependency, packaging, signing, or release-pipeline changes.                                                                                                                                                                                                                                                                                                                                              |
| Go static-analysis gate               | `go vet ./...`                                                                            | Not separately recorded                                                   | Required static analysis for all changes; run before push and whenever Go code or generated Go output changes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Go build gate                         | `go build ./...`                                                                          | Not separately recorded                                                   | Required compilation check for all Go packages; run before push and whenever Go code, generated Go output, or build inputs change.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |

The fast suite intentionally omits the race detector. Use the named extended
tier that matches the changed area, and record the tiers run in the PR
description.
