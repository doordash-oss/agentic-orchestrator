# Desktop Parity Matrix

Frozen inventory of the previous client outcomes the desktop app must preserve, captured at Phase 1 Task 1 and re-audited in Phase 12 against the last complete terminal-client baseline, commit `7caa76a1540a85bf48f0924ab9c9ec49b9589eb8`. Superseded source paths were intentionally removed with the previous client.

Rules:

- Rows are **frozen**: later phases update `Status` and `Automated evidence`
  but may not silently drop or reword a capability. Phase 12 completed only
  cells that explicitly said an interaction or contract was pending, then
  sealed every capability, prior behavior, interaction, contract, and platform
  cell in `desktop/cutover-frozen.json`. Additions require a new row, not an edit.
- `Status` is `delivered` only when the automated evidence exists and passes;
  everything else stays `pending`. Gaps are never waived by omission.
- "Contract" names the authoritative server surface from `api/openapi.yaml`
  (paths as of Task 1) or the desktop IPC channel from
  `desktop/src/shared/ipc.ts`. `contract pending` marks capabilities whose
  REST surface is still being extended.
- Platform scope is `macOS+Linux` unless a platform-specific behavior is
  called out.
