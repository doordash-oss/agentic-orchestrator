# UI Design Playbook

> **This file is an index.** The actual guidance lives in the topic files below.
> Start here, then read the files that match the surface and phase you are
> working in.

This playbook is for beautiful UI work across web, mobile, desktop, terminal,
and TUI surfaces. It is grounded in official design systems and
usability/accessibility research, not framework-specific taste.

## Read By Task

| File | When to Read |
|------|-------------|

| [interaction-and-trust.md](interaction-and-trust.md) | Navigation, forms, feedback, onboarding, errors, multi-step flows |
| [accessibility-and-inclusion.md](accessibility-and-inclusion.md) | Always; contrast, focus, semantics, targets, reduced motion, multimodal feedback |
| [platforms-and-adaptation.md](platforms-and-adaptation.md) | Web/mobile/desktop/responsive work or cross-platform product design |

| [sources.md](sources.md) | When you need authoritative references, examples, or rationale |

## Core Idea

A beautiful interface usually has these traits:
- the primary task is obvious within a few seconds
- the scan path is intentional
- typography and spacing establish rhythm without noise
- feedback is timely and proportional
- accessibility and platform fit are visible in the design, not bolted on later
